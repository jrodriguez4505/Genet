Genet

One organism.
Many stems.

The question is not how many agents you can run. It is whether a second one is doing new work.

The idea

Most stacks treat headcount as capacity. Genet treats it as a cost. A task starts with one lead agent, the orchestrator. The lead may propose sub-agents, each with the skill its sub-task needs. Policy gates in code decide whether any of them run. Default is a single agent.

The team is small, and every agent can switch skills, with specialists added only when a sub-task needs one. The lead owns the roster, the goal stays fixed while the method changes, and work fans out only when the task has independent parts.

Who decides what

Models propose; code disposes. A model only ever returns a JSON artifact. Everything that changes the team, the tools or the budget is decided in code and written to an audit log.

Three gates

can someone else → should we → could we. It is admission control for sub-agents, in that order, failing closed. "Should we" needs a measurable reason: either the operator declared that the sub-tasks must stay isolated, or the material does not fit in one agent's context. Could-we is last on purpose.

Terms

LeadOrchestrator. The only agent that proposes changes to the team.
Sub-agentA worker with an isolated context. It never sees the other sub-agents' work.
GatesAdmission control: already covered, a named failure, and tier, budget, cap and skill.
SkillA role brief and tool profile. Tools are read-only and allowlisted.
Budget tierTight: a single agent. Normal: may replan. Open: may fan out.
Run logTrace and audit log. Every gate record, tool call, verdict and halt.

Proving it

taskorg compare runs the same tasks three ways: one agent, an always-split crew, and Genet. The model, tools and budget are the same for all three. The claim is that Genet matches the better baseline's accuracy at close to single-agent cost. A perfect simulated reader shows the mechanism. With a roomy context, Genet stays a single agent at 1.19× its cost. With a tight one, a single agent fails where the material overflows, and Genet fans out on exactly those tasks, at 0.91× the cost of a crew. The claim stays a claim until a live run says so.

python -m taskorg.cli compare --dry-run          # plan and call ceiling
python -m taskorg.cli compare --adapter sim      # structural cost at $0
python -m taskorg.cli compare --adapter live     # a real model
